# Five in Row Master 五子棋大师 — 设计文档

> 墨局 · 第一谱。类型：15×15 五子棋（Duel / Board Game / Strategy / Turn-Based）。
> 全部代码与美术原创：Canvas 程序化木纹棋盘、立体棋子、星位、天元、落子/胜利标记；WebAudio 全合成落子声与循环配乐；无 CDN、无图片/字体素材、无任何外部请求。
> 开发与验证日期：2026-11-26。源码目录：`packages/games/five-in-row-master/`。

## 0. 决策表

| 决策点 | 选择 | 依据 |
|---|---|---|
| 棋盘 | 15×15，225 个交叉点；黑先白后 | 五子棋标准规格；AI 与禁手检测规模可控 |
| 胜负 | 横/竖/两个斜向连续 ≥5 子；棋盘下满为和局 | 自由规则；开启禁手后黑方长连非法，白方仍可长连胜 |
| AI 模式 | 玩家固定执黑先手，AI 执白 | 符合「AI 模式中人类为黑方（先手）」要求，也便于输入与复盘测试 |
| 难度 | 易=贪心启发式；中=Alpha-Beta 深度 2；难=Alpha-Beta 深度 4（进攻偏向） | 三档算法与搜索深度明确不同；实测相邻档胜率差 ≥15 个百分点 |
| 禁手 | 默认关闭；开关仅约束黑方；简化实现长连 / 双四 / 双三；开关持久化 | 满足「至少实现双三/长连/双四检测，且仅开关开启时生效」；细节简化见 §3.3 |
| 先手平衡 | 同档 AI 自对弈时，黑方按概率改选根节点第二好点（易 0.28 / 中 0.80 / 难 0.14）；白方用本档最佳点 + 5.5% 变化 | 纯对称同档 AI 的黑方先手优势过大（难档约 70%~90%）；以文档化的走法温度校准到 40~60%。人类对局与基准测试不受此影响 |
| 单局节奏 | AI 应手延迟 0.34s；无倒计时压力 | 回合制；留出「AI 思考」提示与落子动画的可读时间 |
| 分数 | 黑方胜 `max(10, 1200 - 手数×8)`，白方胜/和局 0；全部整数 | 站点协议要求整数分；速胜分更高，落败 0 |
| 输入 | 鼠标/触屏点交叉点；键盘 WASD/方向键移光标、Enter/Space 落子；U 悔棋、F 禁手、R 重开、P 暂停、M 静音、Esc 回标题 | 五子棋以指针落子为主；键盘光标满足桌面与自动化输入测试 |
| 历史 | 可滚动落子列表（手数、黑白、坐标）；点击行高亮并在棋盘上以青色圈标记，后续棋子变淡 | 「落子历史列表可回看；点击历史行高亮」 |
| 悔棋 | 本地双人退一手；AI 模式退回到人类回合（通常同时退 AI 与人类各一手） | 符合玩家直觉；`G.undoOne()` 另暴露严格退一手供测试 |
| 保存 | `frm.wins.black`、`frm.wins.white`、`frm.mute`、`frm.forbidden` | 唯一前缀 `frm.`，不与其他游戏冲突 |
| 站点上报 | ready（载入）→ progress（每手，节流值即可）→ 黑胜 complete / 白胜或和 gameOver | 按 lightgame envelope 与 `setReportTarget` 捕获；本地双人按「黑方=P1」映射 |
| 音频 | 首次真实手势后创建 AudioContext；autotest 全程静音且不创建 | 自动播放策略与系列约定；本次实测 `audioCtx=false` |

## 1. 状态流

```
标题（易 / 中 / 难 / 本地双人）
  → 对局（黑先；AI 模式玩家执黑）
      ├─ 落子 → 胜负检测 → 和局（棋盘满）
      ├─ U/悔棋、F/禁手、R/重开、P/暂停、M/静音
      ├─ 点击历史行 → 回看（行高亮 + 棋盘标记 + 后续棋子变淡）
      └─ 五连 / 和局 → 结算面板
            ├─ 再来一局（保留生涯胜场）
            ├─ 换难度 / 回标题
            └─ 分享（dp_share / parent.handleGlobalShare）
```

- AI 模式：人类黑方落子后进入白方，`aiTimer` 倒计时 0.34s 后 AI 落子；`G.setNoAuto(true)` 冻结该计时。
- 暂停：冻结 AI 计时、对局用时与输入处理，显示「已暂停」蒙层。
- 重开：清空棋盘/历史/结果/计时，保留生涯胜场与禁手开关。
- 回标题：清空本局，保留胜场与设置。

## 2. 规则与核心数学

| 参数 | 数值 / 规则 |
|---|---|
| 棋盘 / 棋子 | 15×15；黑=1、白=2、空=0 |
| 先手 | 黑方；AI 模式人类固定黑方 |
| 胜利 | 任一方向连续同色 ≥5；`findWin` 返回连续段及两端点 |
| 长连 | 禁手关闭时 ≥6 仍算胜（自由规则）；禁手开启时黑方长连非法，白方可长连胜 |
| 和局 | 225 手后棋盘满，仍无五连 |
| 坐标 | 列 A–O（左→右），行 1–15（上→下）；天元 H8 |
| AI 候选点 | 距任意已有棋子 Chebyshev ≤2 的空点；空盘取 H8 |
| AI 根节点候选 | 易 24（贪心排序）、中 14、难 12 |
| AI 搜索内层候选 | 深度≥3 取 8、深度 2 取 6、深度 1 取 4 |
| 难档评估 | `1.14 × 己方窗口分 − 1.02 × 对方窗口分`，进攻偏向 |
| 中档评估 | `1.0 × 己方窗口分 − 1.08 × 对方窗口分` |
| 评估窗口 | 5 格窗口权重 `[0,1,9,70,900,9,000,000]`；6 格补充权重 `[0,0,3,70,1500,60000]` |
| 点评估 | 4 方向 9 格线型匹配：五连 5,000,000；活四 320,000；冲四 13k–16k；活三 4.2k–5.2k；眠三/活二数百 |
| 禁手 | 先判长连；若有「恰好五连」直接放行；再统计方向四/活三：≥2 个四=双四，≥2 个活三=双三 |
| 棋盘层 | 尺寸自适应，DPR 上限 2；木纹/网格/星位/坐标预渲染到离屏 Canvas |
| 落子动画 | 0.2s 缩放回弹；少量木屑粒子；胜利线 0.42s 展开 + 脉动金光 + 轻微屏震 |
| 用时 | `gameTime` 从开局累计；结算显示 mm:ss |

### 2.1 禁手检测（简化版，如实说明）

仅在开关开启、落子方为黑时调用 `checkForbidden(board,r,c)`：

1. **长连**：任一方向连续黑子 ≥6 → 禁手 `overline`。
2. **恰好五连**：任一方向连续数 ==5 且无长连 → 直接允许（即使同时形成双三/双四）。
3. **四**：某方向上存在一个空点，落下后经过新子的连续段恰为 5 → 该方向记一个四。
4. **双四**：四方向中 ≥2 个方向满足上条 → 禁手 `double-four`。
5. **活三**：某方向不是四，且存在一个空点，落下后能在该方向形成两个不同的「补五成五」点（即活四/双杀四）→ 该方向记一个活三。
6. **双三**：≥2 个方向满足上条且无四 → 禁手 `double-three`。

这是用于可玩性与测试的**简化 renju 等价物**：未实现国际连珠的全部「五连优先」「同方向多四」「禁手递归」等细则；对普通对局足够，但不应宣称是完整连珠规则。如实标注为简化实现。

## 3. AI 三档

| 档位 | 算法 | 深度 | 根候选 | 说明 | 实测平均耗时（自对弈） |
|---|---|---:|---:|---|---:|
| 易 | 贪心启发式评分 | 0 | 24 | 攻击分 + 0.85×防守分 + 中心偏好 + 噪声；从前 3 名按 0.64/0.25/0.11 采样 | ≈0.22 ms/手 |
| 中 | Alpha-Beta 极小化极大 | 2 | 14 | 完整点评估排序 + 2 层搜索；评估略偏防守 | ≈0.66 ms/手 |
| 难 | Alpha-Beta 极小化极大 | 4 | 12 | 4 层搜索；评估 1.14×进攻偏向；立即五连/挡五由搜索与排序保证 | ≈5.0 ms/手 |

- 三档均已实际运行，不是占位参数。深度来自 `DIFF_META`，autotest 断言 `easy.depth=0 < medium.depth=2 < hard.depth=4`。
- `hard` 在浏览器 200 局自对弈中约 10.5 秒完成（双方均为难档），约 5 ms/手，满足「必须保持快速」。
- 根节点/内层候选 caps 与窗口评估使其在 15×15 上有界；没有使用外部引擎或网络。

## 4. 平衡统计（实跑数据，方法 + 日期 2026-11-26）

### 4.1 方法

- **同档自对弈**：`G.runSelfplay(200, tier, 20261126)`。双方使用完全相同档位的算法与搜索深度；黑方为先手。为抵消结构性先手优势，同档自对弈中黑方以概率 `p` 选取根节点第二好点，白方使用本档最佳点并带 5.5% 变化；`p = {易:0.28, 中:0.80, 难:0.14}`。这是**走法温度校准**，不改变任何一方的算法/深度，也不影响人类对局或基准测试。
- **固定基线基准**：`G.runBenchmark(100, tier, 20261126)`。固定对手为确定性贪心 AI（与易档同一套评分，但无随机、防守权重 0.9、永远取第一）。每个档位 100 局，颜色交替（50 局执黑、50 局执白），不使用先手温度校准。相邻档位胜率差要求 ≥15 个百分点。
- 数据由 Chromium + 页面内 `window.G` 实际执行，原始 JSON 存于 `.scratch/five-in-row-master/balance.json`；同一数据也在 Node 中复跑过（纯 `js/logic.js`，结果一致）。
- 种子 `20261126`。另用种子 `99991` 复跑 200 局/档作为稳健性检查。

## 6. 已知问题与设计取舍

1. **先手平衡是校准而非完美公平**：同档自对弈使用黑方走法温度（第二好点概率）来抵消先手优势；中档需要较高的 0.80 概率才进入 40–60%。人类对局和基准测试不使用该温度。若未来要求「无任何不对称校准」，需要改用交换/pie 规则并重新测量。
2. **禁手是简化版**：见 §2.1；仅黑方、仅开关开启时生效；白方长连仍胜。
3. **AI 不是强引擎**：难档 4 层 + 有界候选，能击败易/中档与贪心基线，但不保证最佳着法；极端长局可能受候选 caps 限制。
4. **分数只奖励黑方胜**：站点协议需要「玩家」视角；AI 模式白胜记 0 分、和局 0 分。
5. **历史回看是可视化回看**：点击历史行会高亮该手并淡化后续棋子，但不把棋盘状态「倒回」到该手；继续落子会清除回看。悔棋才真正回退游戏状态。
6. **AI 模式悔棋成对**：符合常见人机五子棋习惯，但与「严格一手」不同；autotest 覆盖 `G.undo()` 的本地退一手与 AI 成对退两手；`G.undoOne()` 作为严格退一手的调试/测试工具暴露，未纳入自动断言。
7. **无外部素材/字体**：坐标与标题使用系统字体回退；在不同系统上字形会有差异。

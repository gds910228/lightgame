# Pong Duel Plus（乒乓对决）— 设计文档

> 灯匠夜游 · 乒乓对决。类型：2D Canvas 物理对拉乒乓（Sports / Arcade / Duel / Local Multiplayer）。
> 全部代码与美术原创：自写球拍积分、拍面角度映射、挥拍旋转、折返预判 AI、三道具与同屏双人输入；
> 程序化深夜纸灯球场、朱红 / 靛蓝球拍、三种道具图标；WebAudio 全合成音效与配乐。
> 零外部请求、零 CDN、零字体 / 图片素材。日期：2026-11-26。

## 0. 决策

| 决策点 | 选择 | 依据 |
|---|---|---|
| 画幅 | 逻辑 960 × 540，等比缩放居中，DPR 上限 2 | 16:9 与站点缩略图一致；横屏触控完整可见 |
| 视角 | 2D 侧视纵向球拍，y 轴上下移动，球左右飞行 | 乒乓最直接的表达；拍面命中点 = 纵向偏移 |
| 局制 | 先到 **11 分** 结束，不设 win-by-2 | 需求明确「先到 11 分」；避免拖长尾局 |
| 发球 | 每分轮换发球（得分方的对手发球），1.35s 倒计时 | 两侧发球数接近，先发优势被压到最小 |
| 物理 | 拍面角度 + 挥拍旋转 + 速度递增 + 顶/底墙反弹 | 对拉越长球越快，必然分出胜负；手感可读 |
| 道具有 | 长拍 / 慢球 / 幻影，三种各带独立图标与计时 | 满足「3 个道具 + 清晰图标/效果」 |
| 幻影 | 纯视觉 3 个幽灵球；真实球完全确定、可击打 | 需求明确「球必须保持确定性、可击打」 |
| AI | 三档参数化：慢跟随 / 折返预判 / 边角控旋 | 差异可被 autotest 数值断言；同档自战可平衡 |
| 输入 | 键盘 W/S、↑/↓；触屏左右分区纵向拖动 + 上下键 | 同屏双人 + 移动端双人/单人 |
| 音频 | 首次真实手势建 AudioContext；全合成 SFX + 四态 BGM | 符合自动播放策略与系列约定 |

## 1. 玩法与状态流

```
标题（AI 易 / 中 / 难 或 本地双人）
  → 对局：serve（1.35s 倒计时）→ live（对拉）
  → 得分：progress 上报 → serve（轮换发球）
  → 任一方到 11 分：
       P1 胜 → complete；P2/AI 胜 → gameOver
  → 结算面板：再来一局 / 换难度 / 回标题
```

- **得分**：球心越过左/右边界（`x < -r` 或 `x > W + r`）。P1 守左、P2 守右。
- **对拉**：每次球拍命中 `rally + 1`；得分时若 `rally > bestRally` 则写入本地纪录。
- **发球**：得分后发球权交给失分方；每分轮换（即得分方的对手发球）。
- **暂停**：P 或右上角按钮，冻结球、球拍、计时、倒计时与粒子；再按继续。
- **重开**：R 或结算按钮；比分、回合、道具、球位、球拍全部复位。
- **静音**：M 或右上角按钮；静音偏好写入 `pdp.mute`。
- **赛点**：任一方 10 分时 HUD 显示「赛点」。

## 2. 物理与核心数学

逻辑画布 960 × 540；上/下墙内沿 `WALL_TOP = 46`、`WALL_BOTTOM = 494`；球半径 9。

| 参数 | 数值 | 说明 |
|---|---:|---|
| 球拍位置 | 左 x=54，右 x=906；宽 14 | 球拍只沿 y 移动 |
| 球拍基础高度 / 长拍高度 | 84 / 140 px | 「长拍」期间高度变为 140 |
| 键盘球拍速度 | 560 px/s | W/S、↑/↓ |
| 触屏拖动跟随速度 | 1500 px/s | 纵向拖动 / 上下键 |
| 发球速度 | 640 px/s | 角度 ±0.22 rad，y 中心 ±34 |
| 球速下限 / 上限 | 420 / 3000 px/s | 长对拉逐步逼近上限，必然分胜负 |
| 每次命中提速 | `speed×1.13 + 36 + |拍速|×0.06` | 越打越快 |
| 墙面恢复系数 | 0.98 | 上/下墙 |
| 命中角度范围 | `rel × 1.05 rad`（±60°） | `rel=(ballY−paddleY)/(h/2+r)` |
| 挥拍直传速度 | `拍速×0.16` 加到出球 vy | 让上/下挥有明显手感 |
| 旋转强度 | `clamp(拍速×0.85 + rel×24, ±460)` | 拍速为主、命中点为辅 |
| 旋转弯曲 | 每步 `vy += spin·dt`，随后把速度重新归一到 [420, max] | 球会沿弧线拐弯而不是无限加速 |
| 旋转衰减 | `exp(−1.2·dt)` | 约 0.8s 衰减到 38% |
| 慢球 | 拾取瞬间 `速度×0.58`，效果期间球速上限 1200 | 7s |
| 物理子步 | 按球速每步最多 8 子步，每子步 ≤6px | 3000 px/s 也不穿拍 / 穿墙 |

核心数学（autotest 实际执行）：

1. **拍面角度**：左拍命中点偏上（`rel<0`）→ 出球 `vx>0, vy<0`；偏下 → `vy>0`；右拍 → `vx<0`。T3。
2. **挥拍旋转**：上挥 `padVy<0` → `spin<0`；下挥 → `spin>0`。把该旋转注入球后推进 30 帧，`vy` 由 −67 变到 −202（继续向上弯）。T4。
3. **道具时长**：长拍 8s / 慢球 7s / 幻影 6s 全部能设定、衰减到 0；长拍结束高度回 84。T5。
4. **进球**：球越过右边界，P1 +1，进入 serve，发球权给 P2。T6。
5. **边界**：上墙反弹后 `vy>0` 且球留在场内。T24。
6. **旋转衰减**：400 → 120（1s 后约 30%）。T25。

> 关键点：球的「速度」与「方向」分离处理。旋转只改变方向，随后把速度重新归一到合法区间；
> 这样「旋转弧线」不会把球速推到数值爆炸，同时拍面角度仍严格由命中点决定。

## 3. AI 三档

| 难度 | 移速 px/s | 反应间隔 s | 预判系数 | 瞄准误差 px | 边角控旋 edge | 读旋 | 幻影干扰 px |
|---|---:|---:|---:|---:|---:|---|---:|
| 易 | 190 | 0.36 | 0.03 | 86 | 0 | 否 | 52 |
| 中 | 285 | 0.16 | 0.72 | 38 | 0.35 | 否 | 22 |
| 难 | 360 | 0.10 | 0.94 | 12 | 1.00 | 是 | 6 |

- **易（轻拍）**：几乎不预判，目标 ≈ 当前球 y，慢速跟随，误差大。适合第一次上手。
- **中（稳拍）**：把来球沿上下墙 `foldY` 折返，预测到达拍线时的 y（预判系数 0.72），会漏长角度球。
- **难（杀拍）**：预判 0.94 且读取旋转项 `0.5·spin·t²`；用拍面偏心量主动把球打向对手远端角落；
  移动快、反应 0.10s，接近时的拍速自然转成旋转。仍是「可被更快的人类拍速 + 边角旋转」击败的。
- 两侧 AI 使用**相同误差相位**（乒乓的左右镜像只翻转 x，不翻转 y），从而消除先发/后发侧偏差。
- 幻影干扰：当对手拥有幻影时，AI 的瞄准误差按上表增加；真实球路完全不变。
- autotest：三档 speed / reaction / predict / error / edge 严格单调（T13）；相同 30 帧内难档实际位移
  145px，易档 71px（T14）。

## 4. 三种道具

| 道具 | 图标 | 效果 | 时长 | 颜色 |
|---|---|---|---:|---|
| 长拍 | 胶囊 + 上下箭头 | 拾取方球拍 84 → 140 px | 8.0s | 玉青 `#58d8c0` |
| 慢球 | 雪花 / 三向叉 | 球速立即 ×0.58；期间球速上限 1200 | 7.0s | 冰蓝 `#8fd8ff` |
| 幻影 | 三重叠圆 | 3 个幽灵球环绕真实球；纯视觉 + 干扰 AI 瞄准 | 6.0s | 紫晶 `#c59aff` |

- **归属**：球碰到道具时，由「最后击球方」获得（`lastHitter`）。
- **刷新**：场上同时最多 1 个道具；每次清空后 3.5–6.5s 在中间 30%–70% 宽度、y 116–424 内刷新。
- **确定性**：幻影不参与碰撞、不改变球速/旋转/位置；autotest 用同一初始状态跑 40 帧，
  有无幻影的真实球 Δx = 0、Δy = 0（T18）。
- HUD 在左右上角绘制道具图标 + 剩余时间圆弧；场上道具带脉冲圈与中文名。

## 5. 计分、上报与记录

- **比分**：`world.score1 : world.score2`；**先到 11 分**，到达即结束，不做净胜两分。
- **上报 score** = `score1 × 100 + score2`（整数，如 7:8 → 708）。
- **progress** = `max(score1, score2) / 11 × 100`（整数，0–100）。
- **帧序**：`ready`（载入）→ 每次得分 `progress` → P1 到 11 `complete` / P2 到 11 `gameOver`。
- **父页面信封**（`window.parent !== window` 时）：
  `postMessage({source:'lightgame', type:'lightgame:report', payload})`；
  progress → `{kind,data}`；gameOver → `{kind,score,progress:{value},data}`；complete → `{kind,score}`；
  ready 另发 `{source:'lightgame', type:'lightgame:ready', gameId:'pong-duel-plus', v:1}`。
- **桥接**：`parent.handleGlobalShare(score)`、`parent.location.href='/'`；本地别名
  `goHome / clickMore / play68_home / dp_share / show_share` 等（static/play68*.js）。
- **持久化**（唯一前缀 `pdp.`）：
  - `pdp.winsP1`：P1 累计赢下的整局数；
  - `pdp.winsP2`：P2 / AI 累计赢下的整局数；
  - `pdp.bestRally`：历史最长单分对拉拍数；
  - `pdp.mute`：静音偏好。
  - 标题页显示「P1 胜 X · P2 胜 Y · 最长对拉 N 拍」。
  - autotest 结束恢复测试前内存值与 localStorage 原值。

## 8. G 调试钩子

- 推进：`G.step(n, dt)`（含渲染）、`G.upd(n, dt)`（只逻辑）。
- 输入：`G.press(...codes)`、`G.release(...codes)`；触屏指针走同一输入路径。
- 开关：`G.setNoAuto(v)`（冻结发球倒计时与道具自动刷新）、`G.setReportTarget(fn)`、`G.setSeed(seed)`、
  `G.setSeedLocked(v)`、`G.setPowerupsEnabled(v)`。
- 流程：`G.start(mode, diff)` / `G.startMatch(mode, diff)`、`G.setPhase('serve'|'live'|'ended')`、
  `G.forcePoint(side)`、`G.forceWin()`、`G.forceFail()`、`G.goTitle()`。
- 场景：`G.setBall(x,y,vx,vy,spin)`、`G.setPaddle(side,y,vy)`、`G.setScore(a,b)`、`G.setRally(n)`、
  `G.setServeT(t)`、`G.grantPowerup(side,type)`、`G.spawnPowerup(type)`、
  `G.setPowerupField(type,x,y)`、`G.setBestRally(n)`、`G.hitMath(...)`。
- 只读：`G.state()`（每次新建快照，无 getter 展平）、`G.reportLog()`、`G.aiProfiles()`、
  `G.view()`、`G.particlesList()`。
- 自战：`G.runSelfplay(n, diff, {server:'p1'|'p2', seed, p1Diff, p2Diff})`。
- 常量：`W,H,WALL_TOP,WALL_BOTTOM,BALL_R,PADDLE_* ,WIN_SCORE,SERVE_TIME,MAX_BALL,SLOW_CAP`。
- URL：`?autostart=1&mode=ai|local&difficulty=1|2|3`、`?autotest=1`。
- autotest：静音、不创建 AudioContext、固定种子、测完回标题并还原 localStorage。

## 10. 平衡方法与实测数据

### 10.1 方法

- 复用游戏同一份 `js/logic.js` 的 `simulateGame / runSelfplay`，**无渲染、无 DOM、无音频**。
- 环境：Linux x86_64，Node v22.22.3，`node --experimental-default-type=module`。
- 每局：先到 11 分，开启全部三种道具，发球倒计时缩短为 0.28s，单局上限 240s；
  超时按当前比分判胜，平局用种子奇偶确定。200 局/条件。
- 同档自战：`easy/medium/hard` 各跑「先发 P1」200 局 + 「先发 P2」200 局，共 400 局/难度。
- 相邻难度基准：`p1 = 被评估难度`，`p2 = medium 固定基准`，先发 P1，每档 200 局，seed=777001。
- 种子基址 1234567（同档）/ 777001（基准），每局 `seed + i×7919`，保证可复现。
- 复跑命令（工作区）：`node --experimental-default-type=module .scratch/pong-duel-plus/balance.mjs`。

### 10.2 同档自战（200 局 × 2 种先发 = 400 局/难度）

| 难度 | 先发=P1 时先发方胜率 | 先发=P2 时先发方胜率 | 超时局数（240s） | 平均最长对拉 |
|---|---:|---:|---:|---:|
| 易 | 44.0% | 44.0% | 0 / 400 | 3.0 拍 |
| 中 | 52.5% | 50.0% | 1 / 400 | 25.6 拍 |
| 难 | 50.0% | 42.5% | 9 / 400 | 32.1 拍 |

- 6 个「先发方胜率」全部位于 **40–60%** 区间。
- 两侧 AI 使用相同误差相位后，p1-first / p2-first 的偏差显著收敛（此前 medium/hard 曾出现 57.5% / 60%）。
- Chromium 内用 `G.runSelfplay(200, ...)` 复跑同一 200 局方案（先发 P1 / 先发 P2 的 P1 胜率）：
  易 44.0% / 56.0%，中 52.0% / 51.5%，难 50.0% / 57.5%；同样全部落在 40–60%，
  与 Node 无头结果基本一致。

### 10.3 相邻难度基准（各 200 局）

| 对局 | P1（被评估档）胜率 | P2（medium 基准）胜率 | 平均比分 |
|---|---:|---:|---:|
| easy vs medium | 0.0% | 100.0% | 0.08 : 11.00 |
| medium vs medium | **49.5%** | 50.5% | 9.10 : 9.20 |
| hard vs medium | 100.0% | 0.0% | 11.00 : 2.47 |
| easy vs hard | 0.0% | 100.0% | 0.03 : 11.00 |

- 以 medium 基准实测 49.5% 计：
  - 易 → 中相邻差距 = 49.5 − 0.0 = **49.5 个百分点**；
  - 中 → 难相邻差距 = 100.0 − 49.5 = **50.5 个百分点**；
  - 均 ≥ 15pp，且 easy < medium < hard 顺序成立。
- Chromium `G.runSelfplay(200, ...)` 复跑同一基准：easy 0.0%、medium 基准 49.0%、hard 100.0%，
  相邻差距 49.0 / 51.0pp，结论一致。

|---|---:|---:|---:|
| 易 | 58.5s | 74.8s | 0 |
| 中 | 160.9s | 234.6s | 0 |

### 10.5 autotest 缩减版（Chromium 内 `G.runSelfplay`）

- 规模：每难度每先发 24 局（共 144 局），固定 seed=76。
- 同档实测（先发 P1 / 先发 P2 的 P1 胜率）：易 54%/50%，中 50%/50%，难 50%/54%；全部 40–60%（余量 ≥4pp）。
- 基准：easy 0% < medium 基准 50% < hard 100%，差距 100pp。
- 断言 T33（同档区间）与 T34（难度排序 + ≥20pp）在两次 Chromium 运行中均通过。
- 说明：小样本（24 局）固定种子在 Node 与 Chromium 间可能因浮点/引擎差异翻转个别对局，
  因此缩减版断言采用**固定 seed + 固定 Chromium 环境**；完整 200 局统计在两端基本一致
  （见 10.2 / 10.3 的 Chromium 复跑）。两种环境各自内部可复现，结论（40–60% 与难度排序）一致。

## 12. 已知问题与后续

1. **hard 档显著强于 medium 基准**（200 局 100% 胜；平均比分 11:2.47）。这是难度梯度的有意结果；
   人类拍速 560 > hard AI 360，且有触屏直接拖动，仍可通过边角与旋转取胜，但需要人工确认手感。
2. **无头自战 240s 上限**：hard 对 hard 有约 2–4.5% 超时，超时按比分判胜；正式对局无时间上限。
   长对拉球速可达 3000 px/s，属于「fever 对拉」设计。
3. **Node/Chromium 混沌差异**：长局自战对浮点扰动敏感，个别胜负会翻转；文档的 200 局表使用 Node，
   autotest 缩减版使用 Chromium 固定 seed。两者各自可复现，且平衡结论一致。
4. **道具归属依赖最后击球方**：AI 不会主动绕路吃道具，道具主要出现在球路中；这是有意简化，
   避免 AI 为吃道具放弃回球。
5. **幻影偏视觉**：真实球完全确定；对 AI 的干扰体现为瞄准误差增加。部分玩家可能觉得幽灵较淡，
   后续可加大幽灵亮度或加入短暂残影。
6. **触屏双人**：左右分区 + 左右上下键；已支持多点 PointerEvent，但未在真机双人并发测试。
7. **音频未听感验收**：headless 全程静音且不创建 AudioContext；上线前需人工试听并微调音量。
8. **缩略图为真实对局状态截图**：在 hard AI 对拉中先让 AI 真实回球，再将球摆到中场取景；
   不是标题/菜单，也不含任何外部素材。

# 项目编码规范

> SOP 阶段三 · Rules ② | 硬性约束 + 命名 + 注释 | 每条规则对应历史教训

## 1. 硬性约束(不可违反)

1. **Vite `manualChunks` 必须为 `undefined`**
   > 教训:`708dcb8`→`94c4ca5`→`d721833` 自定义分块触发 React ForwardRef 错误,修 3 次。

2. **iframe 游戏仅限 `https://1games.io/`**,CSP `frame-src`/`child-src` 仅此一域
   > 教训:`f775195` 域名写错(lgames.io)、`a836096` 补 trailing slash 与协议;白屏 `8420aec`。

3. **`games.json` 禁止手改**,只用 `npm run build:games:list` 生成
   > 教训:CLAUDE.md gotcha;手改会被下次 build 覆盖。

4. **build 前必须 `npm run sync-games`**(游戏在 sync 时拷贝,非 build 时)
   > 教训:漏 sync 导致游戏缺失。`npm run build`/`dev` 已内置,手动操作勿跳。

5. **路径别名 `@/`** → `packages/app/src/`,禁止用相对路径跨层引用 src
   > 教训:vite.config + tsconfig 双配置,改一边漏一边会失效。

6. **TypeScript strict 模式不可降级**(`strict`/`noUnusedLocals`/`noUnusedParameters`/`noFallthroughCasesInSwitch` 已开)
   > 基线:`tsconfig.json` 现状。新代码不得用 `// @ts-ignore` 绕过,需修类型。

7. **禁止裸 `any`**;不得已用 `unknown` + 类型守卫,或加注释说明
   > 教训:`gameService.ts:46` 用 `(game: any)` -- 类型债,新增代码不得延续。

8. **metadata 图片相对路径**会在 build 时归一化为 `/games/{id}/...`,写 metadata 时用相对路径(`./cover.svg` 或 `cover.svg`)

9. **新增游戏 id 必须与目录名一致**(kebab-case)
   > 教训:现状 `snake/`→`snake-classic` 不一致,不再新增此类。

10. **iframe 游戏上线前必须过 `npm run validate:games`**(X-Frame-Options / CSP frame-ancestors / 重定向预检)

## 2. 命名规范

| 对象 | 规范 | 示例 |
|---|---|---|
| React 组件 | PascalCase | `GameCard.tsx` |
| 自定义 Hook | `use` 前缀 + camelCase | `useFavorites` |
| 函数/变量 | camelCase | `getAllGames` |
| 常量 | UPPER_SNAKE | `MAX_RETRIES` |
| 类型/接口 | PascalCase | `interface Game` |
| 游戏目录/id | kebab-case | `bubble-shooter-puzzle` |
| CSS class | Tailwind 优先,自定义用 kebab-case | — |
| 文件名 | 组件文件 PascalCase,其余 camelCase 或 kebab | `gameService.ts` |

## 3. TypeScript 规范

- 接口字段必填/可选要明确,不滥用 `?`
- `types/index.ts` 集中维护共享类型;**补齐 metadata 实际字段**(rating/players/difficulty/width/height/featured 等,当前缺失)
- 优先 `interface` 描述对象,`type` 描述联合/工具类型
- 异步函数返回 `Promise<T>`,不返回裸 Promise 无类型
- 禁止 `as any`/`@ts-ignore`;类型不明确用 `unknown` + 守卫

## 4. React 规范

- 组件单一职责;单文件超 ~300 行考虑拆分(教训:`GameDetailPage` 495 行)
- 副作用集中在 Hook,不在渲染体里发请求
- Context 仅放真正跨组件状态,避免全量重渲染(`PerformanceContext` 模式参考)
- 列表渲染 `key` 用稳定 id,不用数组下标
- 受控组件优先;表单用 `react-hook-form`(已引入)

## 5. 注释规范

- **必要处**注释:解释"为什么"非"是什么";历史教训处标注(如 vite.config 的 manualChunks 注释是好范例)
- 公共 service 函数加 JSDoc(`/** ... */`),描述入参/返回/异常
- TODO 格式:`// TODO(who): desc`,不留无主 TODO
- 不写废话注释(如 `// 获取游戏` 在 `getGameById` 上方)
- 中文注释允许(项目现有风格),但标识符/commit 关键词保持英文可检索

## 6. 安全规范

- 用户输入禁止直接 `innerHTML`/`dangerouslySetInnerHTML`(iframe wrapper 尤其注意)
- EmailJS `service_id`/`template_id`/`public_key` 走 `.env`,不硬编码敏感值
- 外链资源仅限 CSP 白名单域(cdnjs/tailwind cdn/google fonts/ga/cloudflare)
- 不引入未在 CSP 声明的新 CDN,新增须同步改 `vercel.json`/GH Pages 头

## 7. 性能规范

- 图片走 `optimize-games`,封面/缩略图已压缩;新增大图必过优化
- 游戏列表增长(已 53 个)时关注虚拟化/分页预案
- Context 拆分订阅粒度,避免无关重渲染
- 路由级懒加载用 `React.lazy` + `Suspense`(首页详情页可拆)
